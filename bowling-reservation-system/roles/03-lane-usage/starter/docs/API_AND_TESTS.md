# 3번 담당 - 화면/요청 규격과 테스트

## 1. 구현된 페이지

| URL | 방식 | 내용 | 담당 |
|---|---|---|---|
| `/` | GET | `/lanes`로 이동 | 3번 데모 전용 |
| `/lanes` | GET | 모든 레인 + 점유 현황 | 3번 |
| `/lanes/{laneId}` | GET | 레인 시설 상태 및 배정 예약 목록 | 3번 |
| `/lanes/{laneId}/status` | POST | 레인 시설 상태 변경 | 3번 |
| `/usages` | GET | 전체 이용 기록(최근 100건) | 3번 |
| `/usages/start` | POST | 배정된 레인 이용 시작 | 3번 |
| `/usages/{usageId}/end` | POST | 이용 종료 | 3번 |

화면은 Thymeleaf 폼 방식이고, 사용자가 직접 데이터베이스에 SQL을 보내지 않습니다.

### POST 입력 필드

- 레인 시설 상태 변경: `status` = `이용가능`, `점검중`, `사용불가`
- 이용 시작: `reservationId`(long), `laneId`(long)
- 이용 종료: URL 경로에 `usageId`(long)

### 예상 동작(데모 정책)

- `예약확정` 또는 이미 다른 레인이 시작되어 `이용중`인 예약만 이용 시작 가능
- 취소/완료 예약의 이용 시작 금지
- 예약에 배정된 레인만 시작 가능
- 시설 상태는 `이용가능`이어야 함
- 같은 레인에서 진행 중인 이용이 있으면 시작 금지
- Oracle 모드: 예약시작 30분 전부터 예약 종료시간 전까지만 시작 가능
- 데모 모드: 시간 제한 비활성화(시연 편의)
- 예약에 배정된 모든 레인의 이용이 완료되어야 예약 전체가 `이용완료`
- 여러 테이블 변경은 `@Transactional`로 함께 커밋/롤백

## 2. H2 데모 데이터

- MEMBER 3건
- LANE 10건 (9번=점검중, 10번=사용불가)
- RESERVATION 3건: 1001(1번 레인), 1002(2+3번 레인), 1003(4번 레인, 완료)
- RESERVATION_LANE 4건
- USAGE 1건 (과거 완료)

실행: `mvn test`(자동 테스트), `mvn spring-boot:run`(로컬 웹사이트)

## 3. 자동 테스트 14개

`src/test/java/com/example/bowling/`:

- `LaneUsageIntegrationTest.java`: 기본 데이터, 이용 시작/종료, 다중 레인, 이중 시작, 미배정, 완료 예약, 상태값 검증, 미래 예약 점검 차단, 점검중 레인 시작 차단, 종료 중복 등
- `LaneUsageWebTest.java`: `/lanes`, `/lanes/1`, `/usages` HTML 조회 성공

테스트는 `@ActiveProfiles("demo")`로 H2 메모리 DB를 사용하여 **개인 Oracle 데이터를 변경하지 않습니다.**

> 테스트는 Maven 의존성 다운로드가 가능한 Windows/IDE에서 실행해야 합니다. 문서 작성 환경에서는 Maven/외부 저장소 접근이 없어 자동 테스트 실행 결과를 아직 확인하지 못했습니다.

## 4. 수동 테스트 순서

1. `/lanes` 접속: 1~10번, 9번 점검, 10번 사용불가
2. `/lanes/1`: 예약 1001, 이용 시작 → `/usages` 기록 + 예약 상태 `이용중`
3. 이용 종료 → 종료시간 저장, 예약 상태 `이용완료`
4. `/lanes/2`, `/lanes/3`: 예약 1002의 레인별 이용 시작
5. 첫 레인만 종료 → 예약 상태 `이용중` 유지
6. 두 번째 레인 종료 → 예약 상태 `이용완료`
7. `/lanes/8`: 시설 상태 `점검중`으로 변경 성공
8. `/lanes/1`: 아직 예약 진행 중이면 시설 상태 점검 전환 차단
9. 완료한 기록 다시 종료/같은 배정으로 다시 시작 → 오류 처리

## 5. 참고: Oracle 개인 계정 데이터

기존 더미데이터가 입력되지 않았거나 CHECK 오류가 남아 있으면 Oracle 모드의 일부 기능이 실행되지 않을 수 있습니다. 데모 H2로 먼저 개발하고 **진단 SQL → 제약조건 검증 → Oracle 연결** 순서로 진행하세요.
