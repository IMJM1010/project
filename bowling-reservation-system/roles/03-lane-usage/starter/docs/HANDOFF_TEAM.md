# 3번 담당 → 다른 담당자 인계 문서

## 1번 (DB/회원/공통 환경)에게 요청할 것

- 공통 Spring Boot 패키지명과 Java 버전
- Oracle 접근 방식 (허용된 직접 연결 또는 SSH 터널)
- JDBC 기반 DB 접근 규칙/트랜잭션 구성
- 기존 5개 테이블과 CHECK 제약조건 정상 여부
- `USAGE_SEQ` 생성 권한/번호 발급 방식
- 팀 공통 예외 처리 방식

전달할 것: 본 모듈의 `repository`, `service`, `controller`, `dto`를 공통 패키지로 이동하는 방법.

## 2번 (예약 관리)과 합의할 것

- 이용 시작 가능 예약 상태: `예약확정`, 다중 레인의 경우 `이용중`
- 이용 시작 허용 시간: 현재 예제는 예약 시작 30분 전 ~ 예약 종료 직전
- 취소된 예약은 점유 검사에서 제외, 실제 이용 중인 예약은 취소하지 않는 정책 권장
- 예약 1건에 레인 여러 개가 있으면 각 레인의 시작/종료는 별도 진행
- 레인 하나라도 이용 시작하면 예약은 `이용중`, 모든 레인이 완료되면 `이용완료`
- 시설 상태 변경과 예약 등록/점검 충돌 처리 책임 경계
- 동일 레인 동시 요청의 락(잠금)과 트랜잭션 경계

## 4번 (UI/통계)에게 전달할 것

- `/lanes`, `/lanes/{id}`, `/usages`의 데이터/화면 구조
- 시설 상태(`LANE.lane_status`)와 점유 상태(`USAGE.usage_status`)는 구분
- 레인별 이용횟수, 실제 이용시간 통계는 `USAGE` JOIN 결과 사용
- 공통 CSS/레이아웃은 4번 코드 우선, 이 프로젝트의 `static/css/style.css`는 데모 전용

## 공통 프로젝트에 병합할 때

1. 팀 저장소의 Java 패키지명 확인 후 `com.example.bowling` 경로 조정
2. `controller`, `service`, `repository`, `dto`의 3번 담당 Java 파일만 병합
3. `templates/lanes`, `templates/usages` 화면 병합
4. 데모 전용 `LaneUsageApplication.java`, 중복 `pom.xml`, H2 SQL은 팀 운영 패키지에 병합하지 않음
5. 이미 존재하는 Controller/Service 이름과 충돌 확인
6. DB 설정은 1번 담당자의 환경변수/프로필 설정 사용
7. 기능 브랜치에서 PR 발행 후 2번의 예약 플로우와 통합 검증

## 권장 시연 시나리오

예약 등록(2번) → 예약 레인 확인(3번) → 이용 시작(3번) → 이용 종료(3번) → 레인·이용 통계 확인(4번).

**현재 저장소의 코드는 독립 실행되는 예제이며, 팀 공통 앱과 자동으로 합쳐지는 형태는 아닙니다.**
