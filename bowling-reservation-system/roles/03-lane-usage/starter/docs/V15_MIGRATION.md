# v1.5 lane/usage working branch
- This starter is isolated from roles/01 and 02. Do not merge into main until their schema and service interfaces agree.
- Java 21; Spring Boot 4.2.0 and ojdbc17, aligned with role 01's declared versions. Web MVC and technology-specific test starters replace Boot 3 dependencies. Verify both java -version and mvn -version report JDK 21 before compiling.
- Demo: mvn test; mvn spring-boot:run; http://localhost:8080/lanes, admin / local-demo-only (local loopback only). Set DEMO_ADMIN_PASSWORD to override. Oracle uses active MEMBER account with ADMIN role and BCrypt password_hash; team auth integration pending.
- Oracle initialization is disabled. Run sql/00_check_oracle.sql read-only first. sql/03_v15_schema_fresh_only.sql is only for a personal test schema with no canonical project tables. It refuses existing names. If old tables were preserved as BAK_V15_*, inspect sql/00_check_oracle.sql and use sql/04_prepare_preserved_names.sql only after review. Do not run it if a new table already exists; partial setup needs manual inspection. Oracle DDL commits implicitly. Identity IDs assumed.
- Provisional: 13:00–midnight, no early start, 1–120 minute extension per request, early finish retains booking, NO_SHOW releases allocation, failed reallocation retains booking and flags manager; no automatic cancellation/recovery. Active failure ends existing usage without rewriting history; all-unused blocked until no-show policy agreed.
- Shared lock: all ten lane IDs 1–10 ascending, then member, reservation, allocation rows and usage rows. All scheduling writers must use the same order; reservation and closing teams not updated in this branch. Closing table/guard not implemented pending approval.
- The committed Boot 4.2.0 upgrade has not been built or tested against actual Oracle or H2 in the GitHub editing environment. Run tests before merging. Older docs describe the pre-v1.5 starter; use this document and new SQL as the branch baseline.
- Remaining: team agreement about reallocation for partially used booking, repair recovery, start/attendance and extension rules, no-show allocation, closing, production auth, migration of existing data, integration and concurrent load tests.


- If arrivals exceed capacity before the first usage, confirm attendance and add WAITING assignments using /usages/assign-lane; once capacity is sufficient, start usage. In-use additional lanes are assigned and started together.

- ERD v1.0 / business rules v1.5: exact named constraints in Oracle and H2; CHAR length syntax only in Oracle. MEMBER/RESERVATION fixture tables are for this isolated starter, not the other roles' implementations.
- Extension checks member and all allocated lane conflicts before changing the shared end time. Capacity for a later start counts completed allocations as part of total visited capacity; UNUSED is excluded. This interpretation needs team confirmation. Reallocation only processes eligible CONFIRMED/IN_USE waiting allocations; no automatic retry of REALLOCATION_FAILED. A unique reservation/lane pair means one failed-lane assignment per reservation per maintenance action; no partial reallocation write on candidate absence. Multi-lane batch maintenance/recovery policy remains unresolved.
- Oracle session time zone is Asia/Seoul. Oracle profile binds to loopback for personal testing. Demo disables time window intentionally. New tests use a fixed business clock.
- sql/05_seed_oracle_test_only.sql is opt-in, requires empty member/reservation/allocation/usage tables and ten AVAILABLE lanes. It accepts a locally generated BCrypt hash; no plaintext password is committed. See README. Do not run on a shared database.
- Current branch modifications were not compiled or executed against H2/Oracle by the editor. Re-run all tests locally before integration.

- A two-thread H2 test attempts to start the same assignment and expects one success. Oracle concurrent testing and cross-role reservation writer locking are still required.
