# 3번 담당과 나머지 팀원 연동 협의

## 공통 URL (예정)
| URL | 방식 | 기능 |
|---|---|---|
| /lanes | GET | 레인 목록 |
| /lanes/{laneId} | GET | 레인 상세/예약 일정 |
| /lanes/{laneId}/status | POST | 시설 상태 변경 |
| /usages | GET | 이용 기록 목록 |
| /usages/start | POST | 이용 시작: reservationId, laneId |
| /usages/{usageId}/end | POST | 이용 종료 |

## 1번 (DB/공통 백엔드)
- Java 패키지명, DB 연결 설정, Spring JDBC 및 트랜잭션 규칙 확정
- `USAGE_SEQ` 생성/운영 정책, PK·FK·CHECK 제약조건 확인
- 코드 병합 시 독립 데모용 `pom.xml`, `LaneUsageApplication.java` 중복 복사하지 않음

## 2번 (예약 담당)
- 예약 1건은 1개 이상 레인 배정(`RESERVATION_LANE`)
- **예약확정** 또는 다중 레인 일부가 이용 중인 **이용중** 상태만 추가 레인 시작 가능
- 레인 하나라도 이용 시작하면 예약 전체 = `이용중`
- 배정 레인 **모두 종료했을 때만** 예약 전체 = `이용완료`
- 취소된 예약 이용 시작 거부
- 예약 시작 30분 전부터 종료시각 전까지 이용 시작 허용(팀 협의 후 수정 가능)
- 현재 점유 여부와 시설 점검 상태는 구분
- 동시 요청 충돌을 막기 위한 트랜잭션/락 정책 공유

## 4번 (UI/통계 담당)
- 1~3번 담당자가 기능별 화면을 작성하고, 4번이 공통 CSS/레이아웃을 통일
- `LANE.lane_status` = 시설 상태; `USAGE.usage_status` = 실제 이용 상태
- 통계에 필요한 SQL: 이용 기록 수, 레인별 이용 횟수, 이용시간 (Oracle DATE 차이×24×60)
- JSP나 React 도입 여부는 팀 공통 기술 스택 확정 후 결정; 현 예제는 Thymeleaf

## 후속 테스트 시연
예약 → 레인 배정 → 이용 시작 → 한 레인 종료 → 모든 레인 종료 → 예약 상태 동기화 → 이용 기록/통계 조회.

## 보안/배포
