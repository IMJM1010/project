# 3번 담당 — 레인 · 실제 이용 기록 관리

## 담당 목표
`LANE`의 시설 상태 및 예약 현황을 보여주고, 배정된 레인에 대한 **실제 이용 시작/종료 기록(`USAGE`)**을 관리합니다.

## 할 일 체크리스트
### 1. 레인 관리
- [ ] 1~10번 레인의 시설 상태 목록 조회
- [ ] 시설 상태 `이용가능` / `점검중` / `사용불가` 표시
- [ ] 권한 정책 범위 내 레인 시설 상태 변경
- [ ] 레인별 선택 날짜의 예약/이용 일정 조회
- [ ] 예약 현황과 시설 상태를 함께 표시
- [ ] 점검 상태 변경 시 2번 예약 기능에 반영되는지 확인

### 2. 실제 이용 관리
- [ ] `RESERVATION_LANE`에서 배정된 레인 조회
- [ ] 이용 시작 버튼 → 실제 시작시각 저장, `usage_status='이용중'`
- [ ] 이용 종료 버튼 → 실제 종료시각 저장, `usage_status='이용완료'`
- [ ] 이용 기록 목록/상세 및 회원·예약·레인과의 JOIN 조회
- [ ] 예약 하나에 여러 레인이 있으면 각 레인의 이용 기록을 따로 처리
- [ ] 여러 레인의 상태에 따라 예약 전체 상태를 변경하는 규칙을 2번과 합의

### 3. 비즈니스 규칙/검증
- [ ] 예약에 배정되지 않은 레인은 이용 시작 불가
- [ ] 동일 `(reservation_id, lane_id)` 이용 기록 최대 1개(UNIQUE) 유지
- [ ] 종료시각은 시작시각 이후
- [ ] 시작 전 종료 불가, 이미 종료된 이용 재종료 방지
- [ ] `LANE.lane_status`는 **시설의 상태**; `USAGE.usage_status`는 **이용의 상태**임을 구분
- [ ] 사용 중으로 표시된 예약과 실제 레인별 기록 간 불일치 검사

## 담당 테이블과 관계
- 직접 관리: `LANE`, `USAGE`
- 참조: `RESERVATION`, `RESERVATION_LANE`, `MEMBER`
- 관계: 예약-레인 배정 1건에 대해 이용 기록은 0개 또는 1개

## 화면 (예정)
- `/lanes` — 레인 현황
- `/lanes/{id}` — 레인 상세/예약 일정
- `/usages` — 이용 기록
- 이용 시작/종료: 팀과 HTTP 방식/URL 협의

## 다른 담당자와 협업
- **1번:** 공통 트랜잭션·DB 처리
- **2번:** 예약상태 전이, 예약된 레인 식별자 전달, 취소/이용중 예외
- **4번:** 레인 카드 시각화와 상태 색상/아이콘 통일

## 필수 테스트 시나리오
- [ ] 예약되지 않은 레인의 이용 시작 시도 → 거부
- [ ] 배정된 레인의 이용 시작 → USAGE 행 생성/수정
- [ ] 이용 종료 → 실제 시작·종료 시간 확인
- [ ] 동일 예약·레인 조합 재생성 → 중복 차단
- [ ] 한 예약에 레인 2개 배정 → 2개의 이용 기록 구분
- [ ] 레인 시설 상태 변경이 화면에 정상 반영

## 개발 산출물 (향후)
레인·이용 Controller/Service/Repository, 레인·이용 HTML 화면, 기록 SQL. **현재는 구현 코드가 없는 작업 명세 문서입니다.**
