# 4번 담당 — 공통 UI · 대시보드 · 통계

## 담당 목표
웹사이트 전반의 디자인을 통일하고, **Oracle에 저장된 회원·예약·레인·이용 데이터를 SQL로 집계하여 보여주는 관리자 대시보드**를 구현합니다.

> 주의: 4번이 전체 프론트엔드를 독점하지 않습니다. 1~3번이 각자의 기능 화면을 작성하고, 4번이 공통 레이아웃과 UI 가이드로 통일합니다.

## 할 일 체크리스트
### 1. 공통 UI
- [ ] 사이트 구조 및 공통 메뉴 설계 (대시보드/회원/예약/레인/이용기록)
- [ ] 기본 레이아웃(사이드바·헤더·컨텐츠 영역) 및 반응형 기준
- [ ] 디자인 토큰: 색상, 글꼴, 간격, 버튼, 상태 뱃지 정의
- [ ] 목록/상세/등록 화면의 공통 UI 컴포넌트 가이드
- [ ] 입력 에러, 빈 데이터, 로딩 등 기본 상태 표시 통일
- [ ] 1~3번 담당 화면의 시각적 일관성 점검

### 2. 대시보드
- [ ] 전체 회원 수 및 예약 수
- [ ] 예약 상태별 건수 (`예약대기`/ `예약확정`/ `이용중`/ `이용완료`/ `취소`)
- [ ] 레인 시설 상태별 현황
- [ ] 선택 날짜 예약 일정 및 최근 예약 목록
- [ ] 실제 이용 현황 요약 (USAGE 기준)

### 3. 통계 SQL
- [ ] 회원별 예약 횟수 (`LEFT JOIN`, `GROUP BY`)
- [ ] 예약 0건 회원 조회
- [ ] 예약 횟수 상위 회원 및 `HAVING` 조건 실습
- [ ] 날짜별 예약 건수
- [ ] 레인별 예약/이용 횟수
- [ ] 완료된 이용의 평균 실제 이용시간 (`actual_end_time - actual_start_time` 활용)
- [ ] SQL 결과를 표 또는 간단한 그래프로 시각화

### 4. 통합/시연
- [ ] 화면 이동/메뉴 동작 점검
- [ ] 실제 Oracle 데이터를 화면에 연동 (값 하드코딩 금지)
- [ ] 데이터 0건·NULL·예외 상황에서도 화면이 깨지지 않는지 확인
- [ ] 발표용 데모 순서 및 화면 캡처 준비

## 담당 테이블과 관계
- 조회: 전체 5개 테이블
- 주요 SQL 기술: `JOIN`, `LEFT JOIN`, `GROUP BY`, `HAVING`, `COUNT`, `AVG`

## 화면 (예정)
- `/dashboard` — 관리자 메인
- `/statistics` — 상세 통계(필요한 경우)

## 다른 담당자와 협업
- **1번:** 공통 화면 레이아웃 적용, 회원별 예약 통계
- **2번:** 예약 상태·날짜·레인 배정 정보 전달 방식
- **3번:** 레인 시설 상태 및 이용 기록 표시 방식

## 완료 판단 기준
- [ ] 회원 수·예약 수·레인 시설 상태가 DB 조회 결과와 일치
- [ ] 예약이 없는 회원도 통계에 올바르게 표시
- [ ] 예약 생성·취소 및 이용 시작·종료 후 관련 지표 변화 확인
- [ ] 화면 전체의 공통 메뉴/상태 표현/디자인 일관성 유지

## 개발 산출물 (향후)
대시보드 Controller/Service/Repository, 통계 SQL, 공통 HTML 레이아웃/CSS, 통계 화면. **현재는 구현 코드가 없는 작업 명세 문서입니다.**
