# 팀 개발 규칙 및 초기 작업 순서

## 1. 공통 기술(예정)
- Java 17+ / Spring Boot / Spring JDBC / Oracle 19c
- Thymeleaf / HTML / CSS / JavaScript
- IntelliJ IDEA 또는 VS Code / GitHub
- SQL 파일은 개인 Oracle 계정 및 개발 환경에서 테스트 후 공유

## 2. 브랜치 운영안
- `main`: 실행 가능한 통합본(직접 수정 지양)
- `feature/db-member`: 1번
- `feature/reservation`: 2번
- `feature/lane-usage`: 3번
- `feature/dashboard-ui`: 4번

실제 개발을 시작할 때 기능별 브랜치를 만들고 Pull Request로 병합합니다. 담당자가 서로의 테이블/설정 파일을 임의로 바꾸지 않습니다.

## 3. 먼저 합의할 항목
- [ ] 백엔드 패키지명/Java 버전 및 라이브러리 버전
- [ ] 화면 URL: `/members`, `/reservations`, `/lanes`, `/usages`, `/dashboard`
- [ ] 날짜·시간 표시 형식 및 서버 시간대
- [ ] 예약 상태 변경 담당(2번)/이용 상태 변경 담당(3번)
- [ ] 예약 취소 시 데이터 보존 및 레인 점유 해제 규칙
- [ ] 다중 레인 예약 시 예약 상태와 각 USAGE 상태의 동기화 기준
- [ ] 동일 레인 동시 예약을 막기 위한 트랜잭션 전략
- [ ] 더미데이터 사용 범위, 개인 DB 접근 권한 및 공동 테스트 방식

## 4. 3단계 개발 계획
**1단계 — 기반 구축**
- 1번: Oracle 연결 및 회원 목록
- 2번: 예약 데이터 모델/화면 설계
- 3번: 레인/이용 데이터 모델/화면 설계
- 4번: 공통 HTML 레이아웃/디자인 규칙

**2단계 — 기능 구현**
- 1번: 회원 등록·수정 및 예약 이력
- 2번: 예약·레인 배정과 중복 방지
- 3번: 레인 상태·이용 시작·종료
- 4번: 실제 SQL 집계/대시보드

**3단계 — 통합 검증**
- Oracle 테이블과 웹사이트 데이터 일치 확인
- 6명 예약→레인 2개 배정 시연
- 레인 시간 중복·점검중 레인 예약 거부 시연
- 이용 시작·종료 시 USAGE 변경 확인
- 회원별 예약 횟수·레인별 이용 횟수 통계 확인

## 5. 보안 및 데이터 취급
- 비밀번호, JDBC URL의 민감 접속 정보, SSH 키, 개인 사용자 데이터 GitHub 업로드 금지
- 설정은 환경변수로 관리하고 예제 파일만 공유
- 더미데이터는 실제 개인정보가 없는 가상 데이터 사용
- 기존 Oracle 테이블의 PK/FK/CHECK 제약조건은 임의로 제거하지 않음

## 6. 역할별 완료 보고 예시
- 구현 기능과 접속 URL
- 실행/테스트 방법
- 사용한 테이블과 주요 SQL
- 정상 동작 캡처
- 미해결 이슈 및 다른 담당자에게 필요한 연동 사항

> 이 문서는 초기 업무 분장안입니다. 역할, 일정, URL은 팀 회의에서 합의해 수정할 수 있습니다.
